Мета роботи – вивчити математичні основи та схему безпечного обміну криптографічними ключами по відкритому каналу зв'язку за протоколом Діффі-Хеллмана (DH), дослідити вразливість базового протоколу без взаємної автентифікації вузлів до атаки «Людина посередині» (Man-in-the-Middle, MITM), а також практично відтворити роботу протоколу та перехоплення/модифікацію повідомлень у багатовіконному мережевому симуляторі.

Завдання до роботи:

1. Відтворення класичного протоколу Діффі-Хеллмана на 2 учасників
Нехай загальнодоступними параметрами, узгодженими довіреною стороною (Trust Party), є просте число p = 331 та генератор мультиплікативної групи g = 204.
Покроковий алгоритм формування спільного секретного ключа між Алісою та Бобом:
- Крок 1: Аліса та Боб обирають власні таємні числа в межах [1, p - 1]:
  Аліса обирає a = 46; Боб обирає b = 56.
  На цьому етапі Алісі відомо (p=331, g=204, a=46), Бобу відомо (p=331, g=204, b=56).
- Крок 2: Аліса обчислює свій відкритий ключ A та передає його Бобу через відкритий канал:
  A = g^a mod p = 204^46 mod 331 = 130.
- Крок 3: Боб обчислює свій відкритий ключ B та передає його Алісі:
  B = g^b mod p = 204^56 mod 331 = 296.
- Крок 4: Обидві сторони незалежно обчислюють спільний секретний ключ K:
  У Аліси: K_A = B^a mod p = 296^46 mod 331 = 58.
  У Боба:  K_B = A^b mod p = 130^56 mod 331 = 58.

Обидва абоненти отримують ідентичне значення K = 58, тоді як пасивний перехоплювач, знаючи лише (p=331, g=204, A=130, B=296), не може обчислити K без розв'язання задачі дискретного логарифмування (рис. 1).

2. Відтворення атаки «Людина посередині» (MITM) на протоколі Діффі-Хеллмана
За відсутності автентифікації відкритих ключів активний зловмисник (Attacker) розташовується між Алісою та Бобом і перехоплює весь трафік:
- Зловмисник генерує власні секретні ключі: c1 = 33 (для зв'язку з Алісою) та c2 = 71 (для зв'язку з Бобом).
- Коли Аліса відправляє свій відкритий ключ A1 = 204^46 mod 331 = 130, Зловмисник перехоплює його і замість нього надсилає Бобу свій підставний ключ:
  A2 = g^c2 mod p = 204^71 mod 331 = 325.
- Коли Боб у відповідь відправляє свій відкритий ключ B2 = 204^56 mod 331 = 296, Зловмисник перехоплює його і надсилає Алісі свій підставний ключ:
  B1 = g^c1 mod p = 204^33 mod 331 = 267.
- У результаті замість одного спільного ключа утворюються ДВА різні сесійні ключі, якими одночасно володіє Зловмисник:
  1) Канал «Аліса <-> Зловмисник»:
     У Аліси: K1 = B1^a mod p = 267^46 mod 331 = 64.
     У Зловмисника: K1 = A1^c1 mod p = 130^33 mod 331 = 64.
  2) Канал «Зловмисник <-> Боб»:
     У Боба: K2 = A2^b mod p = 325^56 mod 331 = 139.
     У Зловмисника: K2 = B2^c2 mod p = 296^71 mod 331 = 139 (рис. 3).

Програмна реалізація протоколу Діффі-Хеллмана та атаки MITM на мові Python:

```python
def diffie_hellman_standard(p: int = 331, g: int = 204, a: int = 46, b: int = 56):
    A = pow(g, a, p)
    B = pow(g, b, p)
    K_alice = pow(B, a, p)
    K_bob = pow(A, b, p)
    print(f"A = {A}, B = {B} -> Спільний секрет K = {K_alice} (у Боба: {K_bob})")
    return K_alice

def diffie_hellman_mitm(p: int = 331, g: int = 204, a: int = 46, b: int = 56, c1: int = 33, c2: int = 71):
    A1 = pow(g, a, p)
    B1 = pow(g, c1, p)
    A2 = pow(g, c2, p)
    B2 = pow(g, b, p)
    K1_alice = pow(B1, a, p)
    K1_attacker = pow(A1, c1, p)
    K2_bob = pow(A2, b, p)
    K2_attacker = pow(B2, c2, p)
    print(f"MITM: K1 (Аліса<->Атакер) = {K1_alice}, K2 (Атакер<->Боб) = {K2_bob}")
```

Відповіді на контрольні запитання:
1. Що таке алгоритм Діффі-Хеллмана?
Протокол Діффі-Хеллмана — це криптографічний протокол асиметричного типу, який дозволяє двом або більше сторонам отримати спільний секретний ключ, обмінюючись інформацією через незахищений публічний канал зв'язку.
2. Опишіть схему обміну ключами за протоколом Діффі-Хеллмана.
Сторони узгоджують відкриті параметри: велике просте число p і генератор g. Перший учасник генерує приватне число a і надсилає другому A = g^a mod p. Другий учасник генерує приватне число b і надсилає першому B = g^b mod p. Далі перший обчислює K = B^a mod p, а другий обчислює K = A^b mod p. Обидва отримують однакове число K = g^(ab) mod p.
3. Що таке атака «людина посередині»?
Атака «людина посередині» (Man-in-the-Middle, MITM) — це вид активної кібератаки, коли зловмисник потайки вбудовується в канал зв'язку між двома абонентами, перехоплює, читає і при необхідності модифікує повідомлення, видаючи себе за кожну зі сторін.
4. Які властивості інформації порушуються при атаці «людина посередині»?
Порушуються: 1) Автентичність (сторони спілкуються зі зловмисником замість справжнього адресата); 2) Конфіденційність (зловмисник розшифровує всі повідомлення); 3) Цілісність (зловмисник може непомітно змінювати або видаляти передані дані).
5. Опишіть схему обміну ключами при атаці «людина посередині».
Зловмисник перехоплює відкритий ключ Аліси A1 і надсилає Бобу свій підставний ключ A2 = g^c2 mod p. Одночасно він перехоплює ключ Боба B2 і надсилає Алісі свій ключ B1 = g^c1 mod p. У результаті встановлюються два окремі ключі: K1 = g^(a*c1) mod p між Алісою і зловмисником та K2 = g^(b*c2) mod p між зловмисником і Бобом.
