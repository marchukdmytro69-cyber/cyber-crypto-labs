Програмний код вебсервера авторизації та перевірки JWT (файл lab2_jwt_server.py):

```python
import hashlib
import datetime
import jwt
from flask import Flask, request, jsonify

app = Flask(__name__)

JWT_SECRET = "DmytroMarchuk"
GROUP_LIST_NUMBER = 12
TOKEN_TTL_SECONDS = GROUP_LIST_NUMBER * 60

def sha256_hash(password: str) -> str:
    return hashlib.sha256(password.encode("utf-8")).hexdigest()

USERS_TRIAD = [
    {"id": 11, "login": "Максим", "password_hash": sha256_hash("Марія")},
    {"id": 12, "login": "Марчук", "password_hash": sha256_hash("Дмитро")},
    {"id": 13, "login": "Новак",  "password_hash": sha256_hash("Давід")},
]

@app.route("/login", methods=["POST"])
def login():
    data = request.get_json(silent=True) or {}
    login_input = data.get("login", "")
    password_input = data.get("password", "")

    input_hash = sha256_hash(password_input)
    user = next((u for u in USERS_TRIAD if u["login"] == login_input and u["password_hash"] == input_hash), None)
    if not user:
        return jsonify({"error": "Невірний логін або пароль", "input_sha256": input_hash}), 401

    payload = {
        "id": user["id"],
        "login": user["login"],
        "exp": datetime.datetime.now(datetime.timezone.utc) + datetime.timedelta(seconds=TOKEN_TTL_SECONDS)
    }
    token = jwt.encode(payload, JWT_SECRET, algorithm="HS256")
    return jsonify({
        "message": f"Користувач {user['login']} (id={user['id']}) був успішно авторизований!",
        "token": token
    }), 200

@app.route("/protected", methods=["GET"])
def protected_route():
    auth_header = request.headers.get("Authorization", "")
    if not auth_header.startswith("Bearer "):
        return jsonify({"error": "Відсутній заголовок Authorization: Bearer <token>"}), 401

    token = auth_header.split(" ", 1)[1]
    try:
        decoded = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])
        return jsonify({"status": "Доступ дозволено!", "user_data": decoded}), 200
    except jwt.ExpiredSignatureError:
        return jsonify({"error": "Час дії токена минув!"}), 401
    except jwt.InvalidTokenError as e:
        return jsonify({"error": f"Невалідний токен: {str(e)}"}), 401
```

3. Деконструкція структури JWT та перевірка стійкості підпису до підробки
Згенерований токен складається з трьох Base64Url-кодованих частин (Header.Payload.Signature):
- Заголовок (Header): `{"alg": "HS256", "typ": "JWT"}`.
- Корисне навантаження (Payload): містить `"id": 12`, `"login": "Марчук"`, `"iat"` та `"exp"`.
- Підпис (Signature): обчислюється як `HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), "DmytroMarchuk")` (рис. 3).

Відповіді на контрольні запитання:
1. Що таке JWT?
JWT (JSON Web Token) — це відкритий стандарт (RFC 7519), який визначає компактний та самодостатній спосіб безпечної передачі інформації між сторонами у вигляді JSON-об’єкта, захищеного криптографічним підписом.
2. Структура токена.
Компактна форма JWT складається з трьох рядків у кодуванні Base64Url, розділених крапками (xxxxx.yyyyy.zzzzz): Заголовок (Header), Корисне навантаження (Payload) та Підпис (Signature).
3. Які дані зберігаються в заголовку?
У заголовку (Header) зберігаються метадані токена: тип токена (`"typ": "JWT"`) та назва алгоритму підпису/хешування (`"alg": "HS256"`, `"RS256"` тощо).
4. Які дані можуть передаватися в корисному навантаженні?
У корисному навантаженні (Payload) передаються твердження (claims) про користувача та додаткові параметри: зареєстровані поля (`sub`, `iss`, `exp` – час закінчення дії, `iat` – час видачі) та користувацькі поля (`id`, `login`, права доступу).
5. Назвіть частини підпису.
Підпис формується з трьох компонентів: 1) Base64Url-кодованого заголовка (Header); 2) Base64Url-кодованого навантаження (Payload); 3) секретного ключа сервера (Secret), які передаються у функцію `HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)`.
6. Опишіть схему автентифікації з використанням JWT.
Користувач передає облікові дані (логін/пароль або OAuth-код) на сервер автентифікації. Сервер перевіряє хеш пароля, формує та підписує JWT своїм секретним ключем і повертає токен клієнту. При кожному наступному зверненні до захищених маршрутів API клієнт додає токен у заголовок `Authorization: Bearer <token>`, а сервер перевіряє валідність підпису та термін дії `exp`, надаючи доступ без необхідності зберігати сесію в пам'яті сервера.
